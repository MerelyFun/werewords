# 角色配置与扩展

网站配置本局使用的实体卡种类与数量，不记录任何玩家的身份。镇长为额外公开职务；每名玩家仍持有一个隐藏角色，村民自动补齐剩余人数。

规则依据与网页适配见 [RESEARCH.md](RESEARCH.md)。当前支持先知、狼人、村民、爪牙、观察者、共济会成员、怪物；学徒、占卜师、模仿者尚未实现。

## 统一目录

`src/roles.ts` 的 `roleCatalog` 是配置入口，目录顺序也是夜晚行动顺序。

| 字段 | 用途 |
| --- | --- |
| `id` | 稳定标识，用于配置保存与阶段关联，不能复用已有角色标识。 |
| `name`、`team`、`description` | 显示名称、阵营与简要规则。 |
| `min`、`max`、`defaultCount` | 数量范围及默认值。 |
| `countStep` | 数量步长，默认 1；共济会为 2，因此只能成对加入。 |
| `nightSteps` | 此角色启用时插入的夜晚阶段；村民为空。 |

每个夜晚步骤配置稳定的 `id`、`roleId`、标题 `title`、说明 `description`、播报文案 `speech`、是否显示词语 `revealSecret`、时间类型 `duration`。`duration: close` 使用闭眼等待（默认 4 秒）；`view` 使用看词／行动时间（默认 8 秒）。只有先知和狼人看词，其余已支持扩展角色始终隐藏词语。

普通睁眼／闭眼阶段可复用文件内的 `steps` 构造器。`getNightSteps` 依据配置生成阶段；`normalizeRoles` 过滤未知角色、非法数量，并补齐村民。新增普通角色不必在设置页逐一写控制按钮；删除可选角色时移除目录项，旧设置中的无效标识会被过滤。改变核心角色或引入新胜负规则时仍需修改相应游戏逻辑和测试，不能只改目录。

## 配音延后

当前已有 13 段基础录音，扩展配音按用户要求留待后续。应用检测所选夜晚阶段的 `id` 是否存在于 `src/narration.json`；任一缺失会使整局进入明确的手动预演，夜晚不自动推进，不以别的角色录音代播。

补充扩展配音时，应使用相同阶段 ID 在 `narration.json` 添加文案及静态文件路径，放入对应录音，并更新 `public/audio/manifest.json`。全部选中阶段具备录音、清单就绪且音频加载成功后，自动播报流程才可启用。需验证录音内容与睁眼／闭眼动作一致、跳过停止旧音频、播放完成后再计时。

`npm run voice:cut` 当前按 `docs/audio-cuts.json` 从原始 49.872 秒录音裁剪基础 13 段。该原件不包含扩展角色，不能仅给新 ID 填入旧录音切点。若新增录音来自另一文件，须先扩展裁剪脚本及切点规格以支持该来源，或独立处理新素材并维护清单。不要运行旧单源流程覆盖新增资产清单。

变更后使用实际项目命令 `npm test`、`npm run build`、`npm run voice:check`、`npm run test:e2e` 验证。新增角色重点验证数量限制、夜晚顺序、秘密词遮挡及相关结算条件。
