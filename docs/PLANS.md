# 网页开发计划

状态：调研与初始化已完成；未开始网页实现。日期：2026-09-08。

## 产品方向

用户已确认：线下共用一部手机。首版建议 4–10 人基础角色，自编中文词库，无账号。流程采用传手机查看身份、看完遮挡，夜晚按身份引导查看词语，白天由镇长操作。

## 阶段 0：准备（本轮）

- [x] 调查游戏及官方资料，记录规则版本差异。
- [x] 初始化本地 Git main 分支。
- [x] 保存计划、项目记忆和进度。
- [x] 用户确定网页用途：线下共用一部手机。

## 阶段 1：规则规格与可运行骨架

目标：固定一个规则版本，建立最小可运行页面。

- 将人数配置、镇长隐藏身份、夜晚信息、回答资源、计时和胜负整理成规则表。
- 明确数字发牌改编：是否模拟多一张牌和中心牌，或采用等价分配；记录与实体流程差异。
- 默认建议 Vite + React + TypeScript，选用届时稳定版本并提交锁文件。
- 设计首页、开局设置、私密查看、游戏台、结算五类屏幕。
- 原创中文视觉，移动端大按钮，暗色适合聚会但保持文字对比度。

验收：页面可启动；规则表覆盖镇长为村民、狼人、先知及多狼人情况；构建与类型检查通过。一次提交完成骨架。

## 阶段 2：打通一局

- 输入玩家、校验人数与角色配置，随机分配身份。
- 逐人查看身份并遮挡；选词后按规则展示夜晚信息。
- 自编小型中文词库，含分类与难度，随机选词避免一局中重复候选。
- 游戏台显示倒计时与规则所需回答标记；镇长手动确认猜中。
- 猜中进入狼人指认，未猜中或资源耗尽进入讨论投票，再结算。
- 显式管理状态转换，结算后可重新开局并清空上一局秘密。

验收：人工走通猜中/未猜中两条完整路径；验证指认成功和失败、多人狼人、平票、镇长特殊身份。状态机与胜负判断用针对性单元测试验证。

## 阶段 3：体验完善与验证

- 本地保存人数、难度等设置；默认不持久化秘密身份和词语。
- 倒计时以截止时间计算，浏览器切后台回来校正；刷新时明确重新开局策略。
- 防止误触泄密，确认重新开局，提供规则帮助。
- 夜晚声音引导可作为增强项，浏览器声音不可用时保留完整文字流程。
- 桌面与移动端浏览器检查布局、控制台错误、触屏操作和可访问性。

验收：窄屏无横向溢出；普通操作不泄露上一位身份；后台计时正确；无阻断性控制台错误。运行项目实际提供的构建、类型检查及规则测试。

## 阶段 4：发布 GitHub Pages

前提：网页构建和玩法验证通过，并取得目标 GitHub 账号/仓库与可用授权。

1. 创建或连接用户指定的 GitHub 仓库，设置 remote 并推送。
2. 配置仓库子路径和静态路由策略，确保直接打开或刷新页面不 404。
3. 添加 GitHub Actions 工作流：安装锁定依赖、检查、构建、上传 dist、部署 Pages；实现时核对官方 action 版本与权限。
4. 将 Pages 发布来源设为 GitHub Actions，检查首次运行日志。
5. 打开正式网址，验证资源、移动端及完整一局，再交付链接。

验收：工作流成功，线上可访问，子路径资源正常，README 写明实际访问地址与更新方法。当前不创建空站发布工作流。
